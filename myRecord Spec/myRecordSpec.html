8. Add Future Address (Define a Correspondence or Future Address)

Screen title: Add Future Address

Fieldset legend: Future Address

Guidance text: "If you know that your address is going to change on a given date, then you can specify the new address in advance so that it will take effect automatically from the supplied date. You may define either your home address, Sheffield address, or a temporary correspondence address. A correspondence address is used to redirect mail for a specified period. This address type takes precedence over both the Sheffield and home addresses. All mail is sent to the correspondence address, even if you also have a Sheffield, or home address defined for the same time period. Please supply, both a start date and an end date

when entering a correspondence address. The home and Sheffield addresses only need a start date, though an end date may be entered as appropriate."

Common Patterns & Redesign Notes

Shared Address Fieldset

The following screens share an almost identical address form and could be refactored into a single reusable address component:

Sheffield Address (adds: Residential Type)

Home Address

Landlord's Address

Prospective Address

Future Address (adds: Address Type, Residential Type, Start Date, End Date)

Standard address fields:

Address Line 1–3 , Town , Region/County , Country (dropdown), UK Post Code (split), Telephone , Mobile Phone , Fax , Email

Legacy Fields to Review

Field

Recommendation

Fax

Remove — no longer in common use

Split UK Post Code (two  inputs)

Consider single postcode field with validation, or postcode  lookup integration

Clarify whether this is system-managed or should be user editable

Accessibility & UX Observations

No visible field-level validation messages in screenshots

No asterisks or other required-field indicators visible

Fieldset/legend pattern is used (good for accessibility)

No postcode lookup / address finder integration

Date fields on Future Address have calendar pickers; other date fields do not PIN fields appear to be plain text inputs rather than masked password fields
